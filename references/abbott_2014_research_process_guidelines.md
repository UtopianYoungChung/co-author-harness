## 1. The three-phase model (the spine of the method)

Abbott frames a project as moving through three phases:

- **Preliminary phase** — orientation. You begin design, bibliography, scanning/browsing, reading, and filing **all at once**, not sequentially ("You're like a dog chasing its tail. Don't worry."). The aim is to converge a stable *design document*, not to produce text.
- **Midphase** — the bulk of the work. Each preliminary activity gets its own sustained effort; the project is run **nonlinearly**, governed by the evolving design document rather than by an outline.
- **Endphase** — the project "escapes from the design document": the emerging written text takes over project control and you re-enter the world of **linear argument**. Drafting in the harness's sense begins here.

**Implication for the harness.** The harness's Ph1 (Plan & Draft) presupposes a stabilized design and a seeded reference pool — i.e., Abbott's preliminary→midphase work is *upstream* of Ph1 drafting. This file gives the Planner an explicit account of that upstream work so bootstrap does not jump straight to drafting an unstabilized argument.

## 2. The five parallel preliminary activities

Run concurrently from day one (Abbott, ch. 4):

1. **Design** — the project's puzzles/questions, the conceptualization of the situation, and what would count as an answer. The design document is revised continuously; "after about five iterations, your design document will have stabilized."
2. **Bibliography** — orient yourself; build a preliminary source map before any heavy search. Do *a lot* of bibliography, but not brute-force search yet (§3).
3. **Scanning / browsing** — sample the literature's shape; let serendipity and adjacency surface sources keyword search misses.
4. **Reading** — read generously to understand the field's conversation before reading critically to position your own claim.
5. **Files / organization** — record everything immediately. "The main payoff from careful filing is to free your mind from the task of remembering where everything is. Then you can use your mind to think, to browse, to analyze." Do not trust memory on a substantial project.

## 3. Brute force is a midphase tool, not a preliminary one

"There is no need whatever for brute force in the preliminary phase." Exhaustive, mechanical search (every item matching a query) pays off only **after** a topic or task has been narrowed to the point where most retrieved items will matter. In the preliminary phase, prefer bibliography, scanning, and browsing. Abbott also cautions that migrated-to-digital indexes are usually **keyword indexes** ("the dumbest index possible") — do not assume a promised thesaurus/controlled vocabulary is actually applied; design search strategy accordingly.

## 4. Relationship to the harness snowball (`seed-snowball-discovery`)

Abbott and Wohlin-style snowball are complementary, not redundant:

- The harness's `seed-snowball-discovery` operationalizes the **midphase, narrowed** search — backward/forward citation chasing against a claim register, with saturation stopping. That is precisely the regime where Abbott licenses **brute force**.
- Abbott's **preliminary** activities (design stabilization, orienting bibliography, scanning/browsing) are what should *precede* a snowball run so the seed set is well-chosen. The Planner reads this file to confirm the section's design is stable and a preliminary bibliography exists before dispatching the snowball; otherwise the snowball saturates on a poorly-framed seed.
- Filing discipline (§2.5) maps onto the harness's `references/REFERENCES.md` + `knowledge/LLM wiki/wiki/sources/` substrate: every consulted source is recorded immediately, freeing attention for analysis.

## 5. Analysis (midphase) — pointers
- Abbott's analysis chapter treats coding, taxonomy-building, and the disciplined accumulation of notes into structure. In the harness this maps to the claim register and the wiki concept/source pages; treat analysis as the bridge from a saturated reference pool to the argument the design document now supports — the readiness condition for Ph1 drafting.

## 6. How the Planner uses this file (operational checklist)
Before dispatching Ph1 drafting or a snowball run on a fresh section, the Planner confirms:
1. A **design document / stable question** exists for the section (≈5 iterations of refinement, per §1).
2. A **preliminary bibliography** exists (orienting sources recorded in `references/REFERENCES.md`).
3. **Filing discipline** is in place (sources logged, not held in memory).
4. The search regime is **phase-appropriate** — browsing/bibliography in preliminary, brute-force snowball only once the section's claims are narrowed (§3–§4).
A section failing 1–2 is not yet ready for Ph1 drafting; the Planner records the gap rather than drafting an unstabilized argument.
