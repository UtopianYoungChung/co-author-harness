# M1–M3 Planning Phase: Quick Start

**For:** All Faculty of Information research projects, especially those making disciplinary placements, theoretical transfers, or claims of methodological integration.

**When to use:** Start of a new project, before drafting begins.

**Time commitment:** M1 (1–2 sessions), M2 (1–2 sessions), M3 (1 session).

---

## What Has Changed: Argumentative Rigor at Planning Time

**Old approach:** Draft first, get external feedback, then fix argumentative gaps.

**New approach:** Catch argumentative gaps during planning (M1–M3), before drafting begins. By the time you write M4 (the draft), the argumentative skeleton is solid.

## The Workflow

### **M1 — Project Memo (1–2 sessions)**

**Goal:** Define the problem, identify tensions, name exemplars.

**What the Checklist asks:**

1. **Exemplar enumeration (if you're making a disciplinary placement claim):**
   - You: "This problem belongs in Information Science"
   - Checklist: "Name 2–4 research programs that already do this work"
   - You: "Orlikowski's sociomaterial practices, Baumer et al.'s algorithmic accountability, Khovanskaya's labor-focused information studies"
   - ✓ Done

2. **Premise mapping (identify potential tensions):**
   - You: "Premise A: Actors are provisional. Premise B: We model actors."
   - Checklist: "What logical question does A+B create?"
   - You: "If actors are fluid, what does a static model capture?"
   - Checklist: "Will this paper resolve it or defer it?"
   - You: "Resolve it — models capture current dependencies, not stable entities"
   - ✓ Done

**After M1, run the Planner feedback gate:** The Planner records attributable user/advisor feedback and verifies the independent current-byte centroid/governing-policy evaluation before requesting revision or approval.

---

### **M2 — Annotated References (1–2 sessions)**

**Goal:** For each source, document its origin, its role, and (if borrowed) its justification.

**What the Checklist asks:**

1. **Framework transfer justification:**
   - You cite: Haslam et al. 2013 (interpersonal humanness perception)
   - Checklist: "Why does this social psychology framework apply to your problem?"
   - You: "Haslam models how traits of humanness are attributed in social contexts. The transfer is: if software systems encode presuppositions about user humanness traits (e.g., 'economically rational' vs. 'has discretionary judgment'), those presuppositions can strip away humanness traits just as social perception does."
   - ✓ Done — transfer justified in the annotation

2. **Epistemological clarity:**
   - You cite: Seeber et al. 2020 (algorithmic management in platform work)
   - Checklist: "Is this evidence, framing, or illustration?"
   - You: "Evidence — empirical study showing systems reshape professional authority"
   - ✓ Labeled in annotation
   
   - You cite: Constructed loan-officer case (from your own thinking)
   - Checklist: "Is this evidence, framing, or illustration?"
   - You: "Illustration — constructed scenario grounded in evidence from platform work, clinical systems, policing."
   - ✓ Labeled in annotation with empirical backing noted

**After M2, run the Planner feedback gate:** The Planner records attributable user/advisor feedback, verifies the independent current-byte policy evaluation, and checks whether each framework transfer is justified and each source is epistemologically classified.

---

### **M3 — Structured Outline (1 session)**

**Goal:** Map out the argument skeleton with argumentative rigor baked in.

**What the Checklist asks:**

1. **Alternative positions addressed:**
   - You argue: "Information is the right disciplinary home"
   - Checklist: "Who might disagree? What alternatives exist?"
   - You: "STS, organizational studies"
   - Checklist: "Where in the outline do you differentiate?"
   - You: "§4 names Information's three-part methodological edge: (a) requirements modeling, (b) situated-practice analysis, (c) interpretive scholarship. Each is something Information does routinely; alternatives do 1–2."
   - ✓ Done — outline shows differentiation

2. **Tension resolution:**
   - From M1, you had: "If actors are provisional, what does the model capture?"
   - Checklist: "Where in the outline do you resolve this?"
   - You: "§2 'Provisional Actors and Models' resolves it by clarifying: models capture current dependencies/constraints (not static entities); staleness occurs when dependencies shift; governance question is: who updates?"
   - ✓ Done — tension appears in outline with resolution

3. **Illustration flagging:**
   - You plan to use: loan-officer case study
   - Checklist: "Is it flagged as illustrative? Is empirical support specified?"
   - You: "§2.3 Loan-Officer Case [ILLUSTRATIVE SCENARIO]. Realism grounded in: Seeber et al. (platform work), Herrmann & Pfeiffer (clinical decision support), predictive policing literature."
   - ✓ Done — flagged and grounded

**After M3, run the Planner feedback gate:** The Planner records attributable user/advisor feedback and checks whether alternatives, tensions, and illustrations are handled. The Evaluator first engages after Ph2 entry.

## What Happens Next (M4–M5)

**M4 — Draft:** You write against the explicit argumentative skeleton from M3. By now, the hard work is done.

**M5 — Submission-bound review:** SAFEGUARD_LAYER checks consistency, well-formedness, citation attribution, and abstract specificity. Reflector's Check-Ownership Audit surfaces any residual risks.

## Common Questions

**Q: Do I have to do M1–M3?**
A: M1–M3 are the normal planning chain. A milestone may be resolved as `not_applicable` only when a higher-authority record authorizes that outcome and records the reason, scope, and substitute evidence required by `MILESTONE_FEEDBACK_HANDOFF_PROTOCOL.md`. Absence or informal omission is `MISCONFIGURED`, not permission to proceed.

**Q: What if I already have a draft?**
A: You can still run the M1–M3 checklist on the draft to identify gaps. It's less efficient than planning first, but it works.

**Q: What if the checklist doesn't apply to my paper?**
A: Some checks are conditional (for example, exemplar enumeration applies only to a disciplinary-placement claim). Record a non-applicable check through the governing criterion's authorized resolution, including its reason and substitute evidence where required; do not silently omit it.

**Q: How long does this take?**
A: M1 typically 1–2 sessions (memo + feedback loop). M2 typically 1–2 sessions (annotate references + feedback). M3 typically 1 session (outline + feedback). Total: 3–5 sessions vs. 8–10 sessions of drafting and revision when the planning chain is not completed first.

## Getting Started

1. **Read** `AGENT_ORCHESTRATION.md` §10 to see what the Planner checks and how milestone handoffs coordinate with Ph1.
2. **Read** `.paper-package/research_notes/lessons_learned.md` (L-P1, L-P2, L-P3) to understand *why*.
3. **Use** `M1_M2_M3_ARGUMENTATIVE_RIGOR_CHECKLIST.md` as your playbook for each milestone.
4. **Complete** the Planner-owned feedback gate, explicit approval, and policy-correct handoff representation at the end of each milestone; effective `audited` requires F9, while effective `derived` accepts without F9 by default and treats any explicitly requested packet as optional non-consumed evidence. Preserve the real source of user/advisor feedback.

## Integration with the Package

These planning checks feed into the review pipeline:
- M1–M3 argumentative rigor → M4 draft is architecturally sound
- M4 draft + DETERMINISTIC_CHECKS → no mechanical errors
- M4 draft + SAFEGUARD_LAYER → consistency, well-formedness, attribution, specificity verified
- M5 submission-bound → Check-Ownership Audit ensures no residual gaps

The system is designed so that by submission time, argumentative rigor and technical soundness have both been verified.
