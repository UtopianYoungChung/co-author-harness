## 1. Problem statement

v0.10.0 shipped the snowball-driven reference scaffolding (SK-33 `seed-snowball-discovery`, SK-34 `claim-coverage-audit`, SK-35 `extend-snowball-incremental`, SK-36 `inherit-snowball-from-wiki`) and routed Phase 1 / Phase 2 dispatch through the new skills with eight-stage developer testing during S1–S6. Pilot validation on a fresh project end-to-end was deferred to v0.10.0 RC carryover; v0.10.1 maintained the deferral; v0.10.2 ships this protocol so the replay can run cleanly when scheduled.

The replay's purpose is **integration validation**, not unit testing — the unit-level behaviour of each skill was verified during v0.10.0 stage testing. The replay exercises the Ph1 → Ph2 → Ph3 ladder on a manuscript that has not seen the snowball ladder during development, so any integration defect (skill chain coupling, phase_state schema gaps, dispatch fanout edge cases) surfaces in observable form.

The replay also materialises the first full H advisory cycle on a real project, which feeds `aggregate_h_calibration.py` (v0.10.2-S2) for the eventual flag-retirement decision.

## 3. Clean-room workspace setup

The replay runs in a workspace separate from the harness development tree to avoid cross-contamination:

```
B:\Agents\<pilot-project>\
├── manuscript\
│   └── main.md (or main.tex)
├── research_notes\
│   ├── directives.md
│   └── glossary.md (optional)
├── references\         # SK-33 outputs land here
├── reviews\            # all review artefacts (overlay outputs, calibration logs)
└── .plugin\            # harness install (via /plugin marketplace add or .plugin file)
```

**Setup steps:**

1. Create `B:\Agents\<pilot-project>` directory.
2. Copy or author `manuscript/main.md` (or `.tex`).
3. Author `research_notes/directives.md` with at minimum: `t1_pstage_declaration` (P0 / P1 / P2), `register_class` (technical / mixed / non-technical), and any project-specific overrides. The PROJECT_BOOTSTRAP.md template at `references/PROJECT_BOOTSTRAP.md §2.8` is the canonical reference.
4. Install the harness via `/plugin marketplace add B:\Agents\co-author-harness` (now WORKING after v0.10.1 source-format fix; v0.10.0 RC's marketplace.json source-field slip is the reason this protocol could not run earlier). Verify `/plugin-commands` lists 16 commands.
5. Initialise phase_state: run `/run-phase-1` from the pilot project root. The harness creates `reviews/phase_state.json` with the v0.10.0 18-field schema.

## 4. Protocol — Ph1 → Ph2 → Ph3 ladder

### 4.1 Phase 1 entry

- Run `/seed-snowball-discovery` (SK-33). Outputs land at `references/REFERENCES.md` with snowball table seeded from the manuscript's load-bearing constructs.
- If the pilot manuscript candidate has wiki-community-link metadata in `directives.md`, SK-36 `inherit-snowball-from-wiki` auto-invokes pre-SK-33 (Phase 0 pre-seed per the v0.10.0 S6 wiring); otherwise SK-36 no-ops with reason code `NOT_WIKI_LINKED`.
- Phase 1 exit: validator gate (4 scripts; 0 blockers required); `phase_state.json` shows `current_phase: Ph1` → `Ph2` transition with `references_initialized: true`.

### 4.2 Phase 2 entry

- Run `/run-phase-2`. The phase-runner dispatches the SK-34 `claim-coverage-audit` (manually-invokable per v0.10.0 S3 spec) on operator request, then SK-35 `extend-snowball-incremental` auto-dispatches on `BELOW_THRESHOLD` outcome from the audit.
- Track the `claim-coverage-audit` outcome class: CLEAN / BELOW_THRESHOLD / AUDIT_FAILED / IDEMPOTENT_HIT (per v0.10.0 S4 binding decision (a)). The four-outcome handler at `agents/planner.md §Phase 3.8` decides the dispatch envelope.
- Track inline parallel SK-35 fanout cap (default 8 per `max_parallel_extend_snowball` in classification.md per v0.10.0 S4 binding decision (b)).
- Phase 2 exit: `phase_state.json` shows `current_phase: Ph2` → `Ph3` transition with `last_coverage_score` populated; cross-round regression hook armed for the next iteration (per v0.10.0 S4 binding decision (c)).

### 4.3 Phase 3 entry

- Run `/run-phase-3`. The Generator drafts; the Evaluator runs Step 8.5 SAFEGUARD Check 8 with the accessibility-overlay (A–H Sub-checks, scoped per `register_class`).
- Sub-check H runs at full procedure (post-grace-period if `h_advisory_cycles_observed >= 1`; in grace mode if first H run on this project per v0.10.1 spec). The §9e H pre-filter (v0.10.2 S1) feeds H step 1 with the per-passage bundle; passages with no fired probes short-circuit to NULL/CLEAN.
- The S1.5 lay-term policy tightenings are active: load-bearing-Latinate whitelist; three-class concrete-referent definition with construct exclusion; signpost orienting/contribution split with orienting-clause Ph2-binding; register-shift signposting marker.
- Reviewer adjudicates H findings; per-finding `false_positive_candidate` toggled true/false. The user authors `reviews/h_calibration_<cycle_id>.md` capturing the adjudicated state per the format documented in `scripts/aggregate_h_calibration.py` docstring.
- Phase 3 exit: TerminalSignoffRow gate per `PHASE_PROTOCOL.md §3.3.3`. H findings are recorded but advisory under `advisory_until: H_two_revision_cycles` (do not gate signoff on this first cycle).

### 4.4 Optional second cycle (advisory-period close)

If the user chooses to run a second revision cycle on the same manuscript, the H advisory cycle count increments to 2 and the `aggregate_h_calibration.py` script can be run for the first time with both criteria potentially satisfied. The retirement-decision adjudication (per `2026-04-27-h-flag-retirement-decision.md` §4 template) becomes possible.

## 5. Metric set

The replay records the following per-phase telemetry. Each metric is captured in the `reviews/` artefact named below.

| Metric | Capture artefact | Notes |
|---|---|---|
| Skill-trigger cost | `.plugin-efficiency.json` (in the harness install) | Cost trace per skill invocation; flags any unexpected dispatch fanout. |
| Coverage score per cycle | `reviews/claim_coverage_<date>_<cycle_id>.md` | Three-set output (covered / synthesis-covered / partially-covered / uncovered) per SK-34. |
| Coverage delta across cycles | Computed from cycle-N and cycle-N-1 reports | Tracks whether snowball ladder converges or diverges across revision rounds. |
| H sub-check firing rate per passage role | `reviews/safeguard_check8_<date>_<cycle_id>.md` §H | Per-role breakdown: signpost orienting / signpost contribution / framing / transition / vignette / anchor. |
| §9e probe-firing distribution | `reviews/deterministic_<cycle_id>.md` §9e | Per-passage bundle; short-circuit count; per-probe firing count. |
| Gate-blocker counts at each phase exit | `phase_state.json` ledger triggers | Counts BLOCKER findings that fired the §3.3.3 gate refusal at each phase exit. |
| H false-positive rate (cycle-1 first-pass estimate) | `reviews/h_calibration_<cycle_id>.md` (user-authored) | Feeds the v0.10.2-S2 aggregator on the second cycle. |

## 6. Exit criteria

The replay closes successfully when:

- **All three phases close gate-blocker-free.** Each `/run-phase-N` exit shows the validator gate green and the §3.3.3 gate did not refuse signoff.
- **Coverage score reaches advisory threshold.** SK-34's coverage score (covered + synthesis-covered) / total reaches the project's `claim_coverage_threshold` (default 0.6 per v0.10.0 schema) by Phase 2 close.
- **H advisory cycle materialised.** `reviews/classification.md` shows `h_advisory_cycles_observed: >= 1` after Phase 3 close. (Two cycles requires running the manuscript through a second revision; this is optional for the v0.10.0 integration validation but required for the v0.10.2 retirement-decision pipeline.)

If any exit criterion fails, the failure is the data the replay was designed to surface — file an issue against the relevant skill or protocol surface, capture the failure mode, and propose a v0.10.3 fix in a follow-up plan doc.

## 7. Known-deferred (out of scope for v0.10.0 pilot replay)

- **SK-32 `run-generator-session`** is not exercised by the pilot replay. v0.8.7 introduced this skill; its pilot validation belongs in a separate session protocol scoped to session-revision flow.
- **`run-phase-3-stability` sub-mode** is not exercised unless the pilot manuscript happens to be at convergence (P2 stage with byte-stable content). The stability sub-mode's Sub-check G/H advisory-only treatment is unit-tested but not pilot-tested.
- **Phase 4 reflector pass** is not exercised by the pilot replay. v0.10.0 scope was Ph1 + Ph2; Ph4 reflector is shipped at earlier versions.
- **Cross-project pre-seed (SK-36) at scale** is not exercised unless the pilot manuscript has wiki-linked metadata pointing at multiple sibling projects. A single-project replay exercises SK-36's no-op path or single-source pre-seed; multi-source pre-seed is a v0.10.3+ protocol extension.
