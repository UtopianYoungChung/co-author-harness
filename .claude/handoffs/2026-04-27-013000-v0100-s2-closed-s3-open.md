## Key Patterns Discovered (S2-specific)

**The section 6.0 Coupling Checklist is now load-bearing for S4.** S2 surfaced empirically what the original architecture had treated as implicit: inserting a Step into a phase-runner skill is an orchestration edit, not a document edit. Four mandatory co-mutation surfaces must be touched concurrently: (1) agents/planner.md (canonical Planner spec — the consumed SKILL.md is NOT authoritative); (2) references/phase_notifications.yaml (any new W-/E- code must be registered); (3) scripts/pre_phase_advance_check.py (any new trigger must be in VALID_TRIGGERS); (4) partial-failure halt-vs-continue semantics reconciled across both files. The checklist applies to S4, S4.5, and any post-v0.10.0 phase-runner-Step-editing stage. S3 is exempt.

**Multi-round semantic-review convergence is normal for under-specified stages.** S2's binding-MAJOR counts per round were 5 -> 7 -> 4 -> 1 -> 0 across five fix cycles. Round 2 exceeded round 1 because the round-1 fixes themselves surfaced deeper coordination gaps. The structural fix (architecture amendment + section 6.0 checklist) was decisive: rounds 3-5 each closed without re-opening architectural questions. For S4, pre-flight by reading section 6.0 before authoring; binding-MAJOR count should converge faster.

**Advisor escalation at round-2 inflection was decisive.** When round-2 fixes produced MORE binding MAJORs than round-1, user invoked Opus 4.7 advisor via advisor:advisor. The advisor diagnosed doc-level under-specification (NOT architectural mismatch) and recommended Path C (amend docs + complete work + add structural prevention). For future stages: when a fix cycle produces more findings than the cycle it was meant to close, escalate to advisor before the next sub-cycle.

**PowerShell ops should use Desktop Commander, NOT user round-trip.** The agent has mcp__Desktop_Commander__* tools (start_process, interact_with_process, read_process_output) that can spawn host-side PowerShell directly, bypassing both Cowork bash-mount staleness AND user-roundtrip latency. Across S2, the agent asked the user to run PowerShell scripts four times — each costing 5-10 minutes of latency. For future stages: use Desktop Commander for harness-script execution; bash MCP only for files the agent itself wrote in-session. Memory: feedback_powershell_via_desktop_commander.md.

Merge tree carried 8558 insertions across 57 files — opposite of S1 empty-merge bug. A short follow-up pushed main, then created the tag (also skipped) and pushed it. For S3: structure script so essential ops (tag creation) happen BEFORE the Read-Host, OR expect a two-step close.
