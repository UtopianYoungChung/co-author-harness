# v0.7.4 Economic-Efficiency Proposal — Eight-Part Package

## 0. Framing

This document files **eight proposed changes** to the `research-writing-harness-claude` plugin targeted at **v0.7.4 consideration**. The proposals are grouped into a single package rather than eight separate files because they compose — (1) and (2) together produce the largest single efficiency win; (3) and (4) together reshape the artefact surface the reviewer must maintain; (5) and (6) together move the harness from a re-derivation-per-invocation model to a hash-checked inheritance model; (7) is a minor schema rationalization; (8) is an operating-discipline adjustment that restructures the user's menu under ceiling-lock.

The proposals do not alter the four-agent contract, the Grounding Protocol, the Lifecycle-Stage Ladder rung semantics, the 15-field `SectionStateObject`, or the 28-trigger enum as such. Every change is **internal to the dispatch and artefact-economy layer**, and each change is shippable independently. No change demotes an existing safety invariant.

## 1. Evidence base: the iter-7 stability-pass cost counterfactual

The T3 iter-7 pass executed on INF3006Y on 2026-04-21 produced **zero manuscript mutations, zero new findings at any severity, a byte-identical manuscript surface against iter-6, and a PASS verdict across all eight SAFEGUARD checks**. The manuscript was already stable at iter-5 (convergence_metric = 0.000 for three consecutive rounds). The pass nonetheless produced seven artefacts totalling several thousand lines of Evaluator, Planner, and Reflector output, ran the full seven-step judgment loop including the Coupling E.2 graph-grounding overlay on a citation set that had not moved, re-derived the Check 8 Sub-check A–F aggregates against an unchanged prose surface, and re-narrated the DND byte-verification across all 13 anchors.

The pass's **marginal diagnostic value** was **one new signal**: the R-Refl-2f-1 advisory on legacy notes-length non-conformance in the pre-v0.7 section log rows. Everything else in the seven artefacts is a re-statement of carry-forward verdicts the prior round already established and that the manuscript hash could have confirmed in a single line.

The pass additionally ran on **Opus 4.7 for every agent role**, including roles — Planner and Reflector-lightweight — for which §12.9 of the Ph.D.-root CLAUDE.md allocates Sonnet 4.6 and Haiku 4.5 respectively. The model allocation was not enforced at dispatch time; the session-level default silently overrode it. The Reflector's own Phase 2f audit did not catch this because the audit inspects `tier_state.json` rows for actor-field validity, not the model that produced the row.

The cost ratio for iter-7 is, by inspection, **one novel advisory per full-seven-step run** at **Opus-4.7 cost across every agent seat**. This proposal package reduces the denominator — the work the seat performs — and rationalizes the numerator — the model that pays for the seat.

## 2. Proposals

### P-1. Planner-dispatched model-allocation enforcement (compose with P-2)

**Claim.** §12.9's tier-conditioned model-allocation table is normatively binding but operationally unenforced. Subagent dispatch via the `Task` tool with an explicit `subagent_type` is the available enforcement surface. The Planner should consult `references/MODEL_ALLOCATION.md §2` in a new **Phase 0.6** preflight, construct a per-role dispatch plan, and dispatch each subagent with the allocation-table model as the `model` override where the harness's four declared subagents (Planner / Evaluator / Generator / Reflector) are invoked.

**Change surface.**

- `agents/planner.md` gains **Phase 0.6: Model allocation preflight**, executed after Phase 0 preflight and before Phase 1 classification routing. Phase 0.6 reads `reviews/tier_state.json` for the target section's `current_tier` and `convergence_metric`, reads `MODEL_ALLOCATION.md §2` for the resolved tier-slot allocation, and constructs a `dispatch_plan` object `{role, tier, model, subagent_type, justification}` for each agent the round requires.
- On any capability-inversion (Evaluator weaker than Generator on the `{Haiku 4.5} ≺ {Sonnet 4.6} ≺ {Opus 4.7}` ordering), Phase 0.6 emits the existing `E-MA-CAPABILITY-INVERSION` and halts.
- On a valid plan, Phase 0.6 writes a `model_dispatch_plan` row (new trigger 29, additive to the enum) to `tier_entry_log` with the plan hash and justification.
- Reflector Phase 2f extends to verify that every row in the iteration carries an actor whose model (recorded in the new `model_used` field of the row) is consistent with the Phase 0.6 plan, emitting `R-Refl-MA-4 dispatch_plan_violation` when the resolved model at a seat diverges from the planned model.

**Invariant preserved.** Four-agent contract (Planner single writer of tier rows; Evaluator never writes prose; Generator sole writer of manuscript; Reflector audits all). Grounding Protocol. Capability-inversion refusal.

**Invariant strengthened.** §12.9 becomes enforceable at dispatch time. The Reflector gains an audit hook against the model that produced each row, not just the row's actor.

**Evidence.** Iter-7 ran on Opus 4.7 for all four seats. Three of those four seats (Planner at T3; Reflector-lightweight; Generator at T3 under a no-edit stability contract) were allocated Sonnet 4.6 or lower by §12.9. The Evaluator-at-T3 seat (the one seat for which Opus 4.7 is the §12.9 floor) did its job correctly. The three over-allocated seats produced no additional signal that a weaker-model dispatch would not have produced.

**Priority.** Highest-leverage when composed with P-2.

### P-2. Stability-pass inheritance as a first-class T3 sub-mode (compose with P-1)

**Claim.** The current `run-tier-3` skill treats every iteration identically. After convergence_metric has cleared `< 0.03` for two consecutive rounds and the manuscript surface is byte-stable, a full seven-step judgment pass is not a review; it is a re-derivation of carry-forward verdicts. The Evaluator's work at iter-7 was, almost entirely, **re-stating what iter-6 already stated** against an unchanged prose surface. An inheritance-and-delta contract is the economically rational operating mode at this point in the T3 loop.

**Change surface.**

- New skill `run-tier-3-stability` **OR** additive flag `--mode stability` on the existing `run-tier-3` skill. The user invokes it explicitly (`/run-tier-3 --mode stability` or `/run-tier-3-stability`). It never triggers automatically — the user retains the climb/pause/terminate decision; stability-mode is a *how*-question, not a *whether*-question.
- **Precondition gate (hard).** The Planner admits the skill only when `convergence_metric < 0.03` has held for `N ≥ 2` consecutive prior rounds, Check 8 aggregate is PASS or BORDERLINE in the most recent full pass, and no BLOCKER is open anywhere. Any failure drops through to full `run-tier-3`.
- **Execution contract.**
  - Step S-0. Compute manuscript hash of `manuscript/main.md` against the fingerprint recorded in the prior iteration's consolidated findings. If the hash differs beyond an acceptable threshold (e.g., any non-whitespace line changed), **drop through to full run-tier-3** — no shortcut is safe on a mutated surface.
  - Step S-1. Cite the prior round's verdicts *by reference*, not by re-derivation. The Evaluator writes `t3_stability_confirmation_<cycle_id>.md` of ~30 lines: manuscript-hash confirmation, carry-forward verdict register, delta-pass result.
  - Step S-2. Run the delta checks only — the ones that are *not* a function of the manuscript surface: drift accounting (`cumulative_drift_lines_since_approval` update), `[T3-STALE]` computation against `t3_last_activity_at`, Check 8 aggregate **hash** comparison (byte-identical Sub-check A–F counter vector implies PASS inherited; any drift forces a full Check 8 re-run), and Phase 2f on new rows only.
  - Step S-3. The Reflector-lightweight probe runs its Phase 1 grounding audit on the delta set (which, in the degenerate case, is empty and the probe emits a one-line PASS-by-definition verdict), and Phase 2f on the new row(s).
- **Single artefact.** `t3_stability_confirmation_<cycle_id>.md`. No separate deterministic artefact, no separate findings artefact, no separate safeguard artefact, no separate recheck artefact, no separate reflector artefact. The carry-forward verdicts are cited, not copied.
- **Escape hatch.** At any Evaluator escalation — a delta check failing, a Check 8 counter drift, a new grounding finding — the skill drops through to full `run-tier-3` and emits a `stability_mode_escalation` notification.

**Invariant preserved.** The full T3 judgment pass remains available at every iteration; stability-mode is a user-invoked sub-mode, not a replacement. The Reflector's grounding audit still runs. The convergence gate at §3.3.3 is unchanged. The TerminalSignoffRow contract is unchanged.

**Evidence.** Iter-7's seven artefacts carry a single novel signal. A stability-mode pass would have produced one artefact of ~30 lines carrying that same signal.

**Priority.** Highest-leverage when composed with P-1. The two together address roughly 80% of the iter-7 cost overrun.

### P-3. Structured-data-first artefact authoring

**Claim.** The v0.7.0–v0.7.2 artefact templates are prose-first: the Evaluator narrates the audit in paragraphs, and the verdicts/counters surface in-line. This is expensive in token terms *and* makes carry-forward comparison (which is what stability-pass inheritance in P-2 requires) harder than it needs to be. A structured-data-first template reshapes the artefact surface so the diff-able content is machine-readable, and the prose narrates only *new* signal.

**Change surface.**

- Rewrite the templates in `agents/evaluator.md` and `agents/reflector.md` to three parts:
  - **YAML frontmatter** carrying every verdict, counter, and severity-aggregate (extending the already-existing frontmatter block). This is the inheritance substrate for P-2.
  - **Findings narrative** of ~10–20 lines covering **only new signal** — no re-narration of carry-forward verdicts, no re-derivation of DND byte-verifications the prior round confirmed.
  - **Locator-only appendix** for carry-forward items — one line per item citing the prior round's finding ID and resolution.
- Generator artefact templates (`manuscript/revision_log.md` entries) are unaffected.
- The Reflector's Phase 2f audit extends to verify the frontmatter schema per artefact family.

**Invariant preserved.** Full audit trail. Every verdict remains locatable in the artefact. Grounding basis remains cited.

**Invariant strengthened.** Inheritance becomes a hash-check over frontmatter rather than a prose-comparison exercise. The Reflector's P-2 delta pass becomes cheap.

**Evidence.** The iter-7 consolidated findings report contained ~400 lines of prose in which the novel signal was a single paragraph. The remaining ~395 lines re-narrated carry-forward status against iter-6.

**Priority.** Next-highest after P-1/P-2 because it is the substrate those two rely on for clean diffs.

### P-4. Convergence_log journal/synthesis split

**Claim.** `reviews/convergence_log.md` currently serves two roles: (a) an append-only journal of per-iteration events, and (b) a human-readable trajectory synthesis. The two roles have different editing contracts and different access patterns, and they are collapsing on each other. At iter-7 the Trajectory synthesis table had to be re-authored in full each round, which is an expensive write against a document whose journal rows should be immutable.

**Change surface.**

- Split into two files under `reviews/`:
  - `convergence_journal.jsonl` (or `.ndjson`) — append-only structured rows; one row per iteration; fields `{cycle_id, iteration, convergence_metric, check8_aggregate, manuscript_hash, new_findings_count, delta_lines, accessibility_gate_state, timestamp}`. Immutable once appended. Generated on every Planner boundary write.
  - `convergence_log.md` — the Trajectory synthesis document; rewritten **only** at named boundaries: `[CONVERGENCE-STABLE]` surface, retraction, MCR admission, TerminalSignoffRow, manuscript-level ceiling-lock. Between those events the synthesis is frozen.
- Migration: a one-shot script reads legacy `convergence_log.md` entries and backfills `convergence_journal.jsonl`.

**Invariant preserved.** Every iteration remains recorded. The trajectory remains legible at human-relevant boundaries.

**Invariant strengthened.** The journal is now machine-readable; per-iteration Planner writes are O(1) row appends rather than full-document rewrites.

**Evidence.** The iter-7 Trajectory synthesis update at the boundary re-wrote the 7-row summary table in full, none of whose prior rows were changing.

**Priority.** Structural cleanup. Independent of P-1/P-2/P-3; can ship standalone.

### P-5. Context-economy via subagent delegation

**Claim.** Full-file reads and single-purpose probes currently execute in the parent session's context. This compounds — the parent's context grows monotonically across the round, and by the time the Reflector-lightweight probe runs at round close, the context carries every prior read. Subagent dispatch via the `Task` tool with an explicit `subagent_type` is the correct surface: the subagent owns a fresh context, runs the full-file read, returns a compressed verdict, and the parent retains only the verdict.

**Change surface.**

- `agents/evaluator.md` instructs: Steps 0a (DETERMINISTIC_CHECKS) and 0.2 (Coupling E.2 graph-grounding overlay) dispatch via `Task` with `subagent_type: "research-writing-harness-claude:evaluator"` on the relevant file slice; return a structured verdict block.
- `agents/reflector.md` instructs: Phase 1 grounding audit on artefact sets > 3 files dispatches via `Task` with `subagent_type: "research-writing-harness-claude:reflector"`.
- `agents/planner.md` instructs: full-file re-reads of manuscript sections for tier_state.json bootstrap dispatch via `Task`.
- Parent session retains the summary; full-file content stays in the subagent context and is released at subagent termination.

**Invariant preserved.** Full-file reads remain the grounding floor — the read still happens, it just happens in a fresh context.

**Invariant strengthened.** Parent-context growth decouples from artefact-surface size.

**Evidence.** This proposal is independent of P-1/P-2; it is an operating-discipline improvement to agent-file text, not a schema or skill change. Adoptable immediately on the next plugin revision with no migration script.

**Priority.** Immediately adoptable; low-risk. Ship independently.

### P-6. Session-state caching

**Claim.** Every Planner invocation in the current contract re-reads `tier_state.json`, `classification.md`, and the section map from scratch. Across a long round these reads compound. A per-session cache keyed by file-hash reduces the re-read cost without compromising the single-writer contract (reads are not writes; invalidation is by hash-check, not by write-through).

**Change surface.**

- `reviews/.session_cache/planner_state.json` updated on Planner writes to `tier_state.json`; read on subsequent invocations with a hash-check fall-through against the underlying file.
- On hash mismatch the cache invalidates and the Planner re-reads.
- `.gitignore` adds `reviews/.session_cache/`.
- Reflector Phase 2f ignores the cache directory (it is not a ledger artefact).

**Invariant preserved.** Planner as single writer of `tier_state.json`. Read paths remain consistent.

**Invariant strengthened.** Hot-path Planner reads become O(1) with cache-hit.

**Evidence.** Iter-7 Planner invocations re-read `tier_state.json` several times in the course of the round despite no intervening mutations.

**Priority.** Immediately adoptable; ship independently. No plugin-schema change — the cache is an implementation detail beneath the single-writer contract.

### P-7. Boundary-write batching (additive trigger 29)

**Claim.** A T3 iteration boundary currently writes one `t3_iteration_round` row (trigger 17) per active section. On a 9-section manuscript this is nine rows carrying near-identical payloads distinguished only by section identifier. A manuscript-scoped boundary row with a `sections_covered` array is the natural simplification.

**Change surface.**

- Extend the 28-trigger enum additively with trigger 29 `t3_iteration_round_manuscript`. Row payload adds `sections_covered: [heading_path, ...]`; the other six fields unchanged.
- The Planner writes **one** manuscript-scoped row per boundary when every listed section transitions identically (same convergence_metric bucket, same Check 8 aggregate, same accessibility_gate_state). When sections diverge at the boundary, the Planner falls back to per-section rows as today.
- Reflector Phase 2f extends to accept both row shapes; monotonicity semantics unchanged.
- Schema migration is absent-means-unavailable: legacy projects never see the new trigger; new projects at v0.7.4+ see it. No forced migration.

**Invariant preserved.** Monotonicity. Actor-field validity. Single-writer contract. Retraction semantics.

**Invariant relaxed in a controlled way.** One row per boundary instead of N, under an all-sections-transition-identically precondition. Divergent boundaries still write per-section rows.

**Evidence.** Iter-7's boundary (had it been committed) would have written nine identically-parameterized rows; trigger 29 would have written one.

**Priority.** Schema-rationalization; ship with P-4 for a coherent ledger-hygiene release.

### P-8. Active termination surfacing under ceiling-lock

**Claim.** When a project's `default_final_tier == T3` (ceiling-lock case), the current Planner surface at the T3 iteration boundary presents the climb/pause/terminate options in the order the skill was written — climb/iterate/reject/pause. This order is misleading under ceiling-lock because there is no rung above T3 to climb to; iteration past stability adds no signal; and the rationally dominant move is `/t3-terminate`. The Planner should detect the ceiling-lock case and re-order the menu accordingly.

**Change surface.**

- `agents/planner.md` gains **§3.5 Ceiling-lock termination ranking**: after the iteration boundary is presented, if `default_final_tier == T3` AND the most recent Check 8 aggregate is PASS AND `convergence_metric < 0.03` has held for N ≥ 2 consecutive rounds, the Planner emits `[CEILING-LOCK-STABLE]` and re-orders the user-option menu with `/t3-terminate` ranked first, `/t3-iterate` ranked second (with an explicit "expected marginal value: low" annotation), and `/t3-reject` preserved at its current rank.
- The emitted notification cross-references `W-CONVERGENCE-STABLE` without supplanting it — both surfaces may coexist.
- Reflector Phase 2f is unaffected.

**Invariant preserved.** The user retains full agency. No option is removed. Termination remains user-gated and requires the TerminalSignoffRow append.

**Invariant strengthened.** Under ceiling-lock, the Planner stops presenting a climb metaphor that doesn't apply.

**Evidence.** Iter-7 presented Path 1 (approve/iterate) as rank-1 despite the project being ceiling-locked at T3 and the manuscript being byte-stable for three rounds.

**Priority.** Operating-discipline adjustment to agent-file text. Adoptable immediately; low-risk.

## 4. Evidence-adequacy / non-duplication / tier-appropriateness framing

The user directed this proposal file to bypass the Planner's three-filter gatekeeper (evidence-adequacy / non-duplication / tier-appropriateness). The framing is still recorded here for reference:

- **Evidence adequacy.** The iter-7 pass is a single-round observation. Four of the eight proposals (P-1, P-2, P-5, P-6) rest on a single-round signal; a recurrence observation across a second project would harden the evidence. The user may wish to run the same test against INF3001H's next stability pass before committing v0.7.4 to this package.
- **Non-duplication.** P-1 and P-2 are net-new surfaces. P-3 reshapes an existing template contract without changing its informational content. P-4 splits an existing artefact; the migration is idempotent. P-5 and P-6 are operating-discipline changes, not schema changes. P-7 is an additive enum extension. P-8 is agent-file text. None of the eight duplicates an existing v0.7.2 surface.
- **Tier-appropriateness.** Every change stays within the Lifecycle-Stage Ladder's existing rung semantics. No change promotes or demotes a rung. P-2's stability sub-mode is admitted only when its preconditions hold; at all other times full `run-tier-3` is the fall-through.

## 5. Decision surface for the package author

The user's role at v0.7.4 consideration is to decide:

(c) whether to park P-8 for a later operator-experience release given that it reshapes the user-facing menu under ceiling-lock and warrants its own CHANGELOG note.

This file does not prescribe (a), (b), or (c). It files the package.
