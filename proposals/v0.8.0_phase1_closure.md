### Phase 1.3 — α Tier B (chain-depth regression gate)

Extended `scripts/release-gate.sh` with a new Phase 0.8 block (between existing Phase 0.7 syntax checks and Phase 1 bundle build). The extension:

1. Adds a `--ship-intent` flag toggling placeholder enforcement from WARN to BLOCKER.
2. Asserts `.plugin-efficiency.json` exists at plugin root — BLOCKER if missing (clears the v0.7.4.1 audit `efficiency_config_missing` MINOR).
3. Checks `input_tokens_per_second`: WARN on 2000 (placeholder) under default invocation; BLOCKER on 2000 under `--ship-intent`; OK on any other value.
4. Attempts to invoke the plugin-calibrator's `audit-package-speed` via one of three discovery paths (`$PLUGIN_CALIBRATOR_BIN`, `plugin-calibrator` on `PATH`, or `$PEER_ROOT/*/scripts/plugin_quality_check.py`). On success, parses `max_subagent_chain_depth` from the JSON output and BLOCKs if it exceeds the config's `thresholds.max_chain_depth` ceiling (default 15). On no-calibrator, WARN-skips with an explicit message.

Rationale for WARN-skip on no-calibrator (not BLOCKER): the calibrator may not ship on every release host; the ceiling is enforced when the tool is available, not as a pre-condition of running the gate. This preserves ergonomic parity with the existing Phase 0.7 `py_compile` checks (OK/WARN-on-missing, not BLOCKER-on-missing).
